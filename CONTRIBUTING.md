# Contributing

Thanks for taking a look. The process is small.

1. **Run the checks.** `bin/ci` runs the Python and TypeScript tests, the type
   checks and the CLI smoke test. Run it before you open a pull request.
2. **Keep pull requests small and focused:** one change, with its tests.
   For anything bigger, such as a new feature, a protocol change or a new
   dependency, open an issue first so we can agree on the approach.
3. **AI-assisted contributions are welcome.** You must have read the code, run
   it, and be ready to stand behind it as your own. Say in the pull request
   that you used an AI tool. [AGENTS.md](AGENTS.md) is the guide for coding agents.
4. **Licensing:** by contributing, you agree your work is released under the
   [MIT licence](LICENSE), like the rest of the project. There is no CLA and no
   sign-off. Keep third-party notices intact ([NOTICE](NOTICE)).

Security problems go through private reporting, not issues: see
[SECURITY.md](SECURITY.md).
